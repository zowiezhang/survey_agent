# Research Harness 中文使用手册

> 适用版本：`research-harness 0.1.0`  
> 更新日期：2026-08-26  
> 配套文件：[独立 HTML 手册](./使用手册.zh-CN.html) · [异步 Agentic RL 示例脚本](../examples/async-agentic-rl.sh)

Research Harness 是一个以证据为中心的深度网络调研编排器。你给它一个自然语言课题，它会先规划研究范围，再把问题拆成角色化工作包，并发调用 Codex、Claude Code 或 OpenAI Responses 搜索和核验资料，最后生成带叶节点超链接的 Markdown 与可交互 HTML 报告。

它的目标不是宣称“抓取了全网”，而是在公开网页、登录墙、付费墙和搜索盲区客观存在的情况下，尽可能扩大覆盖面，同时明确记录证据、冲突、失败和未解决问题。

## 五分钟开始

### 1. 安装依赖并构建

需要 Node.js 20 或更高版本。

```bash
cd '/Users/zhangzhaowei05/Desktop/test/survey_agent'
npm install
npm run build
```

检查 CLI：

```bash
npm start -- --help
npm start -- research --help
```

### 2. 选择一个已经可用的执行器

Codex：

```bash
codex login
codex --version
```

Claude Code：

```bash
claude auth status
claude --version
```

OpenAI API：

```bash
export OPENAI_API_KEY='你的服务端密钥'
```

### 3. 运行第一个调研

```bash
npm start -- research '调研异步 Agentic RL 当前的学界与工业界研究现状；区分论文实验、厂商自报和独立复测；每个重要结论附原始链接' \
  --harness codex \
  --depth standard \
  --concurrency 4 \
  --heartbeat 5 \
  --out reports/async_agentic_rl.md
```

默认还会在同一目录生成 `reports/async_agentic_rl.html`。HTML 是离线单文件，双击即可打开。

## 系统实际会做什么

一次完整运行依次经过：

```text
自然语言课题 / 本地参考文件
        ↓
范围规划、同义词与查询图
        ↓
角色化任务图与实体分片
        ↓
并发 Evidence Workers
        ↓
第二波来源与引用审计
        ↓
URL 去重、证据账本、冲突与缺口
        ↓
结构化综合与引用校验
        ↓
Markdown + 可交互 HTML
```

几个重要边界：

- `harness` 是真正负责执行规划、搜索、核验和综合的 Agent 运行环境，不只是一个模型名称。
- `maxQueries` 是规划器生成的互补查询簇上限；它不等于最终 subagent 数量。
- `maxAgents` 是角色化工作包总上限；一次 6 查询的 Deep 运行可以生成 64 个工作包。
- `concurrency` 是同一时刻并行运行的外层工作包数量，不是总工作包数。
- 每个 worker 必须提交原子事实、HTTP(S) 来源、置信度、证据限制和未解决问题。
- 报告只允许引用已进入来源注册表的 `S1`、`S2` 等编号，不允许综合器凭空增加链接。

## 安装与运行条件

### 必需条件

| 项目 | 要求 |
|---|---|
| Node.js | 20 或更高版本 |
| npm | 与 Node.js 配套版本即可 |
| 网络 | 所选 Agent 能访问网页搜索/抓取能力 |
| 执行器 | Codex CLI、Claude Code CLI 或 OpenAI API 三选一 |
| 磁盘 | Deep 报告可能达到数 MB，临时 Agent 会话还会占用系统临时目录 |

### 安装

```bash
git clone '<你的仓库地址>' survey_agent
cd survey_agent
npm install
npm run check
```

`npm run check` 会执行 TypeScript 构建和全部离线测试，不会启动真实搜索，也不会消耗模型 token。

### 环境变量

| 变量 | 用途 | 必需性 |
|---|---|---|
| `OPENAI_API_KEY` | OpenAI Responses API 密钥 | 使用 `openai` 时必需 |
| `OPENAI_BASE_URL` | 自定义兼容 API 地址 | 可选 |
| `OPENAI_MODEL` | OpenAI 默认模型 | 可选，默认 `gpt-5.4` |
| `CODEX_COMMAND` | Codex CLI 路径或命令 | 可选，默认 `codex` |
| `CODEX_MODEL` | Codex 默认模型 | 可选 |
| `CODEX_TOKEN_ENV` | 要求运行前必须存在的 token 环境变量名 | 可选 |
| `CLAUDE_COMMAND` | Claude Code CLI 路径或命令 | 可选，默认 `claude` |
| `CLAUDE_MODEL` | Claude Code 默认模型 | 可选 |
| `CLAUDE_TOKEN_ENV` | 要求运行前必须存在的 token 环境变量名 | 可选 |
| `CLAUDE_MAX_BUDGET_USD` | 每次 Claude Code 会话的预算上限 | 可选 |
| `RESEARCH_HARNESS_API_TOKEN` | HTTP 服务 Bearer token | 启动服务时必需 |

项目不会自动读取 `.env` 文件。你可以在 shell 中 `export`，或使用自己的安全 secret manager 注入环境变量。

## 选择 Harness：Codex、Claude Code 或 OpenAI

### Codex

适合已经在本机登录 Codex，希望复用 Codex 的网页研究与终端 Agent 能力的情况。

```bash
codex login

npm start -- research '你的课题' \
  --harness codex \
  --model gpt-5.4 \
  --depth deep
```

Harness 会为每个阶段启动临时 `codex exec`，使用：

- `--ephemeral`
- `--sandbox read-only`
- `--skip-git-repo-check`
- 原生 `--output-schema`
- 原生 `--json` 事件流

临时会话不会修改项目目录，也不会保留 Codex session。

如果你的内部 Codex 配置要求某个 token 变量存在：

```bash
export MY_CODEX_AGENT_TOKEN='...'
export CODEX_TOKEN_ENV=MY_CODEX_AGENT_TOKEN
npm start -- research '你的课题' --harness codex
```

`CODEX_TOKEN_ENV` 填的是“变量名”，不是 token 内容。

### Claude Code / CC

`cc` 是 `claude` 的别名。

```bash
claude auth status

npm start -- research '你的课题' \
  --harness cc \
  --depth deep \
  --subwork hybrid \
  --concurrency 4
```

在 `hybrid` 或 `native` 模式下，Evidence 会话可获得受限的 Claude Code 原生 `Agent` 通道。允许工具只有 `WebSearch,WebFetch,Agent`；结构修复阶段不允许搜索和 subagent。Claude Code 在临时空目录、safe mode、无 session 持久化环境中运行。

### OpenAI Responses API

```bash
export OPENAI_API_KEY='...'
export OPENAI_MODEL='gpt-5.4'

npm start -- research '你的课题' \
  --harness openai \
  --depth standard
```

OpenAI 模式使用内置 web search 和 Structured Outputs，并设置 `store: false`。API key 只从进程环境读取，不接受命令行参数或 HTTP 请求 body 中的 provider token。

### 怎么选

| 需求 | 建议 |
|---|---|
| 已经在本机使用 Codex | `--harness codex` |
| 需要 Claude Code 原生 subagent | `--harness cc --subwork hybrid` |
| 服务端统一通过 API key 调度 | `--harness openai` |
| 先低成本试题目 | 任意 harness + `--depth quick` |
| 追求最大覆盖、可接受长时间运行 | `--depth deep --max-agents 64` |

## 直接运行完整示例

仓库内置了一个真实可执行脚本：

```bash
chmod +x examples/async-agentic-rl.sh
./examples/async-agentic-rl.sh
```

它默认执行：

- 课题：异步 Agentic RL 学界与工业界现状
- Harness：Codex
- 深度：Deep
- 查询簇上限：6
- 工作包上限：64
- 并发：6
- 每个工作包最多 20 条 findings
- 心跳：每 5 秒
- 输出：`reports/async_agentic_rl_example.md/.html`

注意：完整 Deep 示例可能运行一小时或更久，具体取决于 Agent、网络、搜索深度和长尾页面。

### 用 Claude Code 运行同一示例

```bash
RH_HARNESS=cc \
RH_SUBWORK=hybrid \
RH_CONCURRENCY=4 \
./examples/async-agentic-rl.sh
```

### 先跑缩小版

```bash
RH_DEPTH=quick \
RH_MAX_AGENTS=12 \
RH_MAX_SOURCES=6 \
RH_CONCURRENCY=3 \
RH_OUTPUT=reports/async_agentic_rl_quick.md \
./examples/async-agentic-rl.sh
```

### 用脚本调研自己的主题

第一个位置参数会替换默认课题：

```bash
RH_OUTPUT=reports/my_topic.md \
./examples/async-agentic-rl.sh \
  '调研中国 AI Coding Agent 初创公司；覆盖创始人、产品、融资、客户、技术、Benchmark、争议；所有数字附原始链接'
```

### 脚本支持的覆盖变量

| 变量 | 默认值 |
|---|---:|
| `RH_HARNESS` | `codex` |
| `RH_MODEL` | 空，使用 Provider 默认值 |
| `RH_DEPTH` | `deep` |
| `RH_SUBWORK` | `hybrid` |
| `RH_MAX_QUERIES` | `6` |
| `RH_MAX_AGENTS` | `64` |
| `RH_ENTITIES_PER_AGENT` | `12` |

## 如何写一个高质量调研指令

只写“调研某公司”也能运行，但难以定义“完成”。推荐包含七部分：

1. **对象**：行业、公司、人物、论文或事件。
2. **范围**：地区、时间窗、纳入和排除标准。
3. **维度**：技术、融资、人物、产品、客户、Benchmark、风险等。
4. **术语扩展**：要求搜索同义词、别名、缩写、旧称、多语言表达。
5. **证据标准**：一手来源优先，数字/引语/人物身份必须有叶节点链接。
6. **冲突处理**：区分厂商自报、作者实验、独立复测，保留冲突。
7. **交付形式**：时间线、对比矩阵、证据缺口和待验证问题。

可复用模板：

```text
深度调研【主题】截至【日期】的【地区/行业】现状。

覆盖：
1. 概念边界、同义词、缩写、旧称和中英文表达；
2. 关键实体、人物、产品、组织关系和时间线；
3. 数据、训练、算法、Agent、系统工程和 Benchmark；
4. 商业化、客户、融资、估值和法律主体；
5. 研究者/创始人原话及观点变化；
6. 失败模式、反证、安全、监管和未解决问题。

证据要求：
- 优先论文、监管文件、代码仓库、公司公告、完整访谈和客户文件；
- 所有数字、引语、人物身份和关键事件必须附可直达原文的 HTTP(S) 超链接；
- 区分厂商自报、论文作者实验、可靠转述和独立复测；
- 转载不得重复计算为独立证据；
- 找不到证据时明确标注“未证实”，不要推断。
```

`--brief` 适合放受众和决策语境：

```bash
npm start -- research '调研中国具身智能数据公司' \
  --brief '面向早期 VC 投资委员会；重点核验真实客户、融资交割、数据权利和单位经济性' \
  --harness codex --depth deep
```

## CLI 完整参数

基本形式：

```bash
npm start -- research '<topic>' [options]
```

| 参数 | 取值/范围 | 默认值 | 说明 |
|---|---|---:|---|
| `--harness` | `openai/codex/claude/cc` | 继承旧 `provider` 默认 | 首选执行器参数 |
| `-p, --provider` | `openai/codex/claude/cc` | `openai` | 兼容旧调用；推荐改用 `--harness` |
| `-m, --model` | 字符串 | Provider 默认 | 传给所选 Agent 的模型名 |
| `-b, --brief` | 最长 4000 字符 | 空 | 受众、角度、补充问题 |
| `-d, --depth` | `quick/standard/deep` | `standard` | 决定角色和默认预算 |
| `-l, --language` | 2–35 字符 | `zh-CN` | 报告语言 |
| `--max-queries` | 2–8 | 由规划器决定 | 互补查询簇数量 |
| `--max-agents` | 2–256 | 12/32/64 | 角色化工作包硬上限 |
| `--entities-per-agent` | 1–50 | 25/18/12 | 每个 worker 的基线实体上限 |
| `--max-sources` | 2–30 | 6/12/20 | 每个工作包的 findings 上限 |
| `--seed` | 本地 HTML/JSON 路径 | 空 | 导入参考基线 |
| `--subwork` | `delegated/native/hybrid` | `hybrid` | 外层/原生 subagent 拓扑 |
| `--concurrency` | 1–16 | 3 | 外层并发工作包数量 |
| `--include-domain` | 多个域名 | 空 | 提示优先检索这些域名 |
| `--exclude-domain` | 多个域名 | 空 | 排除这些域名 |
| `-o, --out` | 文件路径 | 自动生成 | Markdown 输出 |
| `--html-out` | 文件路径 | Markdown 同名 | HTML 输出 |
| `--no-html` | 开关 | 关闭 | 不生成 HTML |
| `--print-json` | 开关 | 关闭 | 额外打印紧凑 manifest |
| `--log-format` | `human/json` | `human` | 人类日志或 JSONL 事件 |
| `--heartbeat` | 正数秒 | 5 | “仍在运行”心跳间隔 |

多值域名示例：

```bash
npm start -- research '调研 AReaL 的技术与复现状态' \
  --harness codex \
  --include-domain arxiv.org github.com proceedings.neurips.cc \
  --exclude-domain pinterest.com quora.com
```

域名参数是研究约束/提示，不是网络防火墙。最终仍需通过来源审计确认实际 URL。

## 深度、工作包与并发的关系

| 深度 | 默认工作包上限 | 默认每包 findings | 每包基线实体 | 典型用途 |
|---|---:|---:|---:|---|
| `quick` | 12 | 6 | 25 | 试题、术语梳理、初步尽调 |
| `standard` | 32 | 12 | 18 | 常规公司/技术专题调研 |
| `deep` | 64 | 20 | 12 | 全景、投资尽调、复杂技术谱系 |

### 三个容易混淆的参数

- `maxQueries=6`：规划器最多生成 6 条互补查询。
- `maxAgents=64`：查询与专业角色组合、实体分片后最多生成 64 个工作包。
- `concurrency=6`：最多同时运行 6 个工作包。

调高 `concurrency` 主要缩短墙钟时间，但会增加并发进程、请求速率、模型预算和搜索服务压力。调高 `maxAgents` 会直接扩大覆盖面与总成本。

### Subwork 模式

| 模式 | 外层 npm 调度 | Harness 内原生 subagent | 适合场景 |
|---|---|---|---|
| `delegated` | 并发 | 关闭 | 行为最可预测、便于控制费用 |
| `native` | 基本串行 | 支持时开启 | 希望由 CC 内部拆分搜索分支 |
| `hybrid` | 并发 | 支持时开启 | 最大并行度；推荐用于 CC Deep 调研 |

Codex 和 OpenAI 仍由外层任务图保证并发；当前原生 `Agent` 工具通道主要针对 Claude Code。

## 角色化 Subagent 任务图

系统定义八类研究角色：

| 角色 | 核心任务 |
|---|---|
| 生态与实体发现 | 别名、旧称、多语言、人物/公司/产品/投资方关系图 |
| 技术尽调 | 数据、训练、算法、Agent、系统、代码与成熟度 |
| 工商与投融资 | 法律主体、工商变更、逐轮融资、估值口径 |
| 创始人与观点追踪 | 人物消歧、履历、完整访谈、观点时间线 |
| 产品与采用尽调 | 版本、定价、客户、采购、生产部署与停服 |
| Benchmark 独立复核 | 版本、预算、harness、污染、复现与可比性 |
| 反证、风险与合规 | 负面结果、安全、诉讼、监管和反向证据 |
| 来源与引用审计 | 回查叶节点、去重转载、检查引语和数字 |

`quick` 使用生态、技术、反证和来源审计；`standard` 增加工商、人物和产品；`deep` 使用全部八个角色。任务图还会按本地参考文件中的实体分片，防止一个 worker 同时负责过多公司。

来源审计通常作为第二波运行，拿到前序 claim/URL 索引后再回查，而不是与被审计者同时盲搜。

## 导入本地 HTML/JSON 参考资料

推荐显式使用 `--seed`：

```bash
npm start -- research '以参考页为起点，重新核验并扩展中国自进化 AI 公司全景' \
  --seed '/absolute/path/参考资料.html' \
  --harness codex \
  --depth deep \
  --max-agents 64 \
  --entities-per-agent 12 \
  --concurrency 6 \
  --out reports/result.md
```

也兼容把绝对 `.html` 或 `.json` 路径直接写进 topic，但显式参数不容易产生路径歧义。

本地参考文件的作用：

- 提取公司、品牌、法律主体、创始人、别名和旧称。
- 提取融资、观点、产品和技术字段作为待核验基线。
- 按实体分片形成角色任务。
- 不会把参考文件中的陈述自动当成最终事实。

CLI 默认允许本地 seed。HTTP 服务默认禁止；必须在启动时加入：

```bash
npm start -- serve --allow-local-seeds
```

不要对不可信的远程调用者开放本地 seed 能力，因为它允许已认证客户端请求服务读取本机指定路径。

日志含义：

| 标记 | 含义 |
|---|---|
| `[预规划]` | 立即公开的第一版研究骨架 |
| `[规划完成]` | Agent 已返回通过 schema 的查询图 |
| `[任务图]` | 角色、编号和实体分片已生成 |
| `[Agent 活动]` | 会话、网页工具或结构化输出活动 |
| `[仍在运行]` | 定时心跳；不是重复启动 |
| `公开工作笔记` | 可公开的查询/证据策略，不是私密 chain-of-thought |
| `[自动重试]` | 单个输出或调用暂时失败，正在重试 |
| `[工作包失败，已隔离]` | 该包最终失败，其他 worker 继续 |
| `[结构修复]` | 只修 JSON/引用结构，不重复搜索 |
| `[综合]` | 证据采集结束，正在建立 claim-to-source 映射 |

### 调整心跳

```bash
npm start -- research '主题' --harness codex --heartbeat 2
```

太短会产生大量日志；一般推荐 5–15 秒。

### 保存机器可读日志

进度写到 stderr，报告完成提示写到 stdout：

```bash
npm start -- research '主题' \
  --harness codex \
  --log-format json \
  --out reports/result.md \
  2> reports/result.progress.jsonl \
  | tee reports/result.stdout.log
```

每行 JSON 都有 `type` 和 `at`；worker 事件还可能包含 `workerId`、`roleId`、`roleName`、`entityIds`。

## 输出报告如何阅读

### Markdown

主要章节包括：

- 调研元数据与范围边界
- 结论摘要
- 关键发现
- 相关主体与脉络
- 风险、不确定性与反证
- 待进一步验证
- 逐工作包证据账本
- 来源注册表

正文中的 `[S12]` 是可点击引用。每条证据还保留置信度、来源类型、日期和 caveat。报告较长时，先读结论摘要，再用 `S编号` 跳到具体来源。

### 交互式 HTML

HTML 是零依赖独立文件，包含全部数据，可以离线：

- 全文搜索报告和证据。
- 按专业角色和置信度筛选。
- 查看每个 worker 的实体分片与工作契约。
- 按来源域名筛选。
- 展开证据、限制和未解决问题。
- 导出内嵌 JSON。

输出默认规则：

```text
--out reports/topic.md
      └── 自动生成 reports/topic.html
```

自定义：

```bash
--out output/report.md --html-out public/report.html
```

只要 Markdown：

```bash
--out reports/result.md --no-html
```

## 实时 Web 控制台

### 启动服务

生成一个长随机 token：

```bash
export RESEARCH_HARNESS_API_TOKEN="$(openssl rand -hex 32)"
npm start -- serve --host 127.0.0.1 --port 8787
```

浏览器打开：

```text
http://127.0.0.1:8787/ui
```

在页面内填入：

1. SSE API：默认 `/v1/research/stream`。
2. Bearer Token：刚才的 `RESEARCH_HARNESS_API_TOKEN`。
3. Harness、深度、并发、工作包和每包来源。
4. 调研任务、可选 seedPath 和 brief。

控制台提供：

- 总进度、运行时间、活动 subagent、来源数量与最后心跳。
- Planner、各角色 worker 和综合器的独立卡片。
- 实时日志搜索与级别筛选。
- 手动取消当前浏览器请求。
- 完成后搜索报告、按域名筛选来源、下载 Markdown、打开交互报告。

“停止任务”通过浏览器 `AbortController` 中止连接。当前实现不是持久化任务队列；浏览器关闭或服务进程退出后，不保证任务可恢复。

### 局域网/公网注意事项

默认绑定 `127.0.0.1`。如果改为 `0.0.0.0`，必须至少配置：

- TLS 反向代理。
- 网络 ACL 或 VPN。
- 长随机 Bearer token。
- 请求限流、并发配额和费用监控。
- 不向不可信调用者开放 `--allow-local-seeds`。

## HTTP API 与 SSE

所有 `/healthz` 和 `/v1/*` 路由都要求：

```http
Authorization: Bearer <RESEARCH_HARNESS_API_TOKEN>
```

UI 页面 `/` 和 `/ui` 本身可加载，但真正提交任务时仍必须提供 token。

### 同步接口

```bash
curl http://127.0.0.1:8787/v1/research \
  -H "Authorization: Bearer $RESEARCH_HARNESS_API_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{
    "topic": "调研异步 Agentic RL 的学界与工业界现状",
    "harness": "codex",
    "depth": "deep",
    "language": "zh-CN",
    "maxQueries": 6,
    "maxAgents": 64,
    "entitiesPerAgent": 12,
    "maxSources": 20,
    "subworkMode": "hybrid",
    "concurrency": 6
  }' > reports/api-result.json
```

同步响应包含：

```json
{
  "id": "运行 ID",
  "createdAt": "ISO 时间",
  "provider": "codex",
  "topic": "...",
  "markdown": "# 完整报告...",
  "html": "<!doctype html>...",
  "tasks": [],
  "evidenceTasks": [],
  "failedTasks": [],
  "sources": [],
  "queryCount": 64
}
```

`queryCount` 在响应中实际等于角色化任务数量，名称为兼容历史接口保留。

### SSE 流式接口

```bash
curl -N http://127.0.0.1:8787/v1/research/stream \
  -H "Authorization: Bearer $RESEARCH_HARNESS_API_TOKEN" \
  -H 'Content-Type: application/json' \
  -H 'Accept: text/event-stream' \
  -d '{
    "topic": "调研异步 Agentic RL",
    "provider": "codex",
    "depth": "deep",
    "maxAgents": 64,
    "concurrency": 6
  }'
```

事件顺序：

```text
event: connected
data: {"ok":true,"provider":"codex"}

event: progress
data: {"type":"query.started", ...}

event: progress
data: {"type":"heartbeat", ...}

event: result
data: {"markdown":"...", "html":"...", ...}
```

失败时会发送 `event: error`，数据含 `statusCode` 和 `message`，随后关闭 SSE。

### 请求字段限制

| 字段 | 限制 |
|---|---|
| `topic` | 3–500 字符，必需 |
| `brief` | 最长 4000 字符 |
| `harness/provider` | `openai/codex/claude/cc` |
| `model` | 最长 120 字符 |
| `language` | 2–35 字符 |
| `depth` | `quick/standard/deep` |
| `maxQueries` | 2–8 |
| `maxAgents` | 2–256 |
| `entitiesPerAgent` | 1–50 |
| `maxSources` | 2–30 |
| `seedPath` | 最长 2048；服务需允许本地 seed |
| `subworkMode` | `delegated/native/hybrid` |
| `concurrency` | 1–16 |
| `includeDomains/excludeDomains` | 各最多 20 个域名 |

请求 schema 是 strict 的。未知字段会返回 400，provider token 字段也不会被接受。

### 健康检查

```bash
curl http://127.0.0.1:8787/healthz \
  -H "Authorization: Bearer $RESEARCH_HARNESS_API_TOKEN"
```

```ts
import {
  createAgent,
  createCliProgressReporter,
  ResearchWorkflow,

const request: ResearchRequest = {
```

## 质量门槛与自动修复

规划、证据和综合阶段都有 JSON Schema。系统按以下顺序处理不规范输出：

1. 尝试解析原始 JSON。
2. 容忍代码围栏、智能引号和尾逗号等机械问题。
3. 重新进行严格 schema 校验。
4. 如仍失败，启动最多两个 repair 工作包。
5. repair 只修结构和引用，不允许再次网页搜索。

单个 evidence worker 连续失败后会被隔离；其他工作包继续运行，并把失败角色和缺口写入最终报告。

以下情况整次运行会失败：

- 规划器无法生成要求数量的互补查询。
- 证据阶段不足两个不同 HTTP(S) 来源。
- 输出经过容错和两次 repair 后仍不符合 schema。
- 综合器引用不存在的来源编号，且无法修复。
- 渲染后的报告少于两个引用。

来源 URL 会移除常见 `utm_*`、`fbclid` 和 `gclid` 跟踪参数，并按规范 URL 去重。

## 性能、时间与成本调优

### 推荐配置

快速试题：

```bash
--depth quick --max-agents 12 --max-sources 6 --concurrency 3
```

日常深度调研：

```bash
--depth standard --max-agents 32 --max-sources 12 --concurrency 4
```

全景/尽调：

```bash
--depth deep --max-agents 64 --max-sources 20 --concurrency 6
```

### 哪个参数影响什么

| 参数 | 覆盖面 | 墙钟时间 | 总 token/费用 | 机器负载 |
|---|---|---|---|---|
| `maxAgents` 增大 | 明显增加 | 增加 | 明显增加 | 增加 |
| `maxSources` 增大 | 增加单包深度 | 增加 | 增加 | 小幅增加 |
| `concurrency` 增大 | 基本不变 | 通常下降 | 基本不变或略升 | 明显增加 |
| `maxQueries` 增大 | 增加查询维度 | 增加 | 增加 | 随任务图变化 |
| `entitiesPerAgent` 减小 | 分片更细 | 可能增加 | 可能增加 | 增加调度量 |

不要直接把所有参数拉满。先用 quick 检查概念边界和提示词，再用 deep 跑最终交付通常更高效。

长尾 worker 运行十几分钟并不一定是卡死。只要仍有心跳、工具活动或其他 worker 补位，就让它继续；真正失败会出现明确的 retry/failed 事件。

## 安全与凭据

- 不要把 API key/token 写进 topic、brief、命令行参数、HTTP body 或 seed 文件。
- CLI 子进程只继承当前进程环境。
- Codex 使用只读、临时、无持久 session 模式。
- Claude Code 使用临时空目录、safe mode 和工具 allowlist。
- OpenAI 请求设置 `store: false`。
- HTTP 服务端 token 与 Provider key 是两种不同凭据；前者给调用者鉴权，后者只留在服务端。
- UI 中 Bearer token 只保存在当前页面内存，不写入生成报告。
- HTML 运行时使用安全 DOM 写入；来源链接仅接受 HTTP(S)。仍应把 Agent 输出视为不可信输入。

如果日志要长期保存，先检查其中是否含内部课题、公司名、查询词或未公开参考文件路径。

## 常见故障排查

### `command not found: codex`

```bash
command -v codex
codex --version
codex login
```

如果安装在自定义路径：

```bash
export CODEX_COMMAND='/absolute/path/to/codex'
```

### `OPENAI_API_KEY is required`

```bash
export OPENAI_API_KEY='...'
```

确认是在启动 `npm start` 的同一个 shell 会话中设置。

### `RESEARCH_HARNESS_API_TOKEN must be set`

```bash
export RESEARCH_HARNESS_API_TOKEN="$(openssl rand -hex 32)"
npm start -- serve
```

### HTTP 401

检查请求头是否精确为：

```text
Authorization: Bearer 你的token
```

注意多余引号、换行和不同 shell 会话中的变量。

### `Planning agent output did not match the required JSON schema`

当前版本会自动进行本地规范化和最多两次无搜索 repair。若最终仍失败：

1. 检查模型是否可靠支持严格结构化输出。
2. 减少过长、相互冲突的 topic。
3. 指定更合适的模型。
4. 使用 `--log-format json` 保存完整事件诊断。
5. 运行 `npm run check` 排除本地代码回归。

### `Codex evidence run failed`

查看前一条 `[Agent 活动]` 的工具或进程错误。常见原因：

- Codex 登录过期。
- 网络或搜索工具暂时失败。
- 模型输出结构失败。
- 系统并发过高。

框架会自动重试单个工作包；连续失败后只隔离该包。可以先把并发降到 2–4 再重试。

### 长时间显示“仍在运行”

先判断是否真卡死：

- 心跳时间是否更新。
- 是否还有 `web_search/WebFetch` 活动。
- worker 编号是否继续增加。
- 是否有其他工作包完成并补位。

Deep 运行出现 5–15 分钟长尾 worker 是可能的。若所有活动完全停止，可用 `Ctrl+C` 终止 CLI，或在 UI 点击“停止任务”。当前版本不支持断点恢复。

### API 不允许读取 seedPath

启动服务时加：

```bash
npm start -- serve --allow-local-seeds
```

然后使用服务端可见的绝对路径。

### 报告引用多，但来源好像重复

同一个 URL 只会在注册表中出现一次；多次正文引用是正常的。来源审计还会识别转载与同源内容，但无法保证识别所有公司所有权或内容转载关系。查看证据 caveat 和来源类型，不要只看数量。

### HTML 太大或打开较慢

Deep HTML 会内嵌全部证据，数 MB 属正常。可以：

- 使用 Markdown 做主阅读版本。
- 降低 `maxAgents` 或 `maxSources`。
- 用浏览器全文搜索/角色筛选缩小范围。
- 使用 `--no-html` 只生成 Markdown。
