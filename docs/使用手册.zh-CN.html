1. 五分钟开始

进入项目、安装依赖并构建：

cd '/Users/zhangzhaowei05/Desktop/test/survey_agent'
npm install
npm run build
npm start -- research --help

使用已经登录的 Codex 运行第一个标准调研：

codex login

npm start -- research '调研异步 Agentic RL 当前的学界与工业界研究现状；区分论文实验、厂商自报和独立复测；每个重要结论附原始链接' \
  --harness codex \
  --depth standard \
  --concurrency 4 \
  --heartbeat 5 \
  --out reports/async_agentic_rl.md
运行过程中终端会持续显示规划、worker、查询、来源、重试、心跳与综合进度。完成后会同时生成 Markdown 和同名可交互 HTML。

2. 系统实际会做什么

课题 / Seed
规划与同义词
角色任务图
并发检索
来源审计
引用综合
MD + HTML
  • harness 是真正执行研究的 Agent 环境，不只是模型参数。
  • maxQueries 控制互补查询簇；maxAgents 控制角色化工作包总量；concurrency 控制同时运行数。
  • 每个 evidence worker 返回原子 claim、HTTP(S) 来源、置信度、caveat 和证据缺口。
  • 第二波来源审计回查 DOI、PDF、公告、commit、榜单行、访谈正文或时间戳等叶节点。
  • 综合器只能引用来源注册表中的 S1、S2 等编号。
框架不会承诺“搜索了全网”。登录墙、付费墙、索引盲区、网页变化和私有数据库始终可能形成缺口；正确行为是记录缺口，而不是编造完整性。

4. 选择 Harness

Codex

复用本机 Codex 登录。每阶段使用临时、只读、ephemeral codex exec，原生 JSON 事件与 output schema。

Claude Code / CC

cc 是 claude 别名。Hybrid 模式同时启用外层调度与受限原生 Agent 通道。

OpenAI Responses

使用内置 web search、Structured Outputs 与 store:false，适合服务端 API 调度。

# Codex
npm start -- research '主题' --harness codex --depth deep

# Claude Code 原生 subagent + 外层并发
npm start -- research '主题' --harness cc --depth deep --subwork hybrid --concurrency 4

# OpenAI Responses
OPENAI_API_KEY='...' npm start -- research '主题' --harness openai --depth standard

Codex 和 CC CLI 的账号登录由各自工具负责；Research Harness 不接管或保存明文 token。

5. 完整示例脚本

仓库包含 examples/async-agentic-rl.sh，可复现“异步 Agentic RL 学界与工业界现状”的 Deep 调研。

chmod +x examples/async-agentic-rl.sh
./examples/async-agentic-rl.sh
默认规模

Deep、6 查询簇、64 工作包、6 并发、每包 20 findings、5 秒心跳。

默认输出

reports/async_agentic_rl_example.md 与同名 HTML。

运行时间

完整 Deep 实例可能运行一小时或更久，取决于网络、Agent 和页面长尾。

切换到 Claude Code

先运行 Quick 缩小版

RH_OUTPUT=reports/async_agentic_rl_quick.md \

RH_OUTPUT=reports/my_topic.md \

6. 如何写高质量调研指令

最好明确对象、时间/地区、研究维度、同义词扩展、证据等级、冲突处理和交付结构。

深度调研【主题】截至【日期】的【地区/行业】现状。

覆盖概念边界、同义词/旧称/多语言；人物与组织关系；数据、训练、算法、Agent、系统和 Benchmark；产品、客户、融资；观点、反证、安全、监管和开放问题。

所有数字、人物身份、引语和关键事件必须附可直达原文的 HTTP(S) 链接。优先论文、监管文件、代码、公告、完整访谈和客户文件；区分厂商自报、作者实验、可靠转述和独立复测；转载不得重复计为独立证据；找不到时标记未证实。

用 --brief 传递受众与决策角度，例如“面向早期 VC 投资委员会，重点核验真实客户、融资交割和单位经济性”。

9. 角色化 Subagent

生态与实体发现

规范名、别名、旧称、多语言、人物/产品/投资方关系。

技术尽调

数据、训练、算法、Agent、系统、代码、成熟度与失败边界。

工商与投融资

法律主体、工商变更、逐轮融资、投资方和估值口径。

创始人与观点

人物消歧、履历、完整访谈、原话上下文与观点变化。

产品与采用

版本、定价、客户、采购、生产部署、停服和采用指标。

Benchmark 复核

榜单版本、预算、工具权限、harness、污染与独立复现。

反证、风险与合规

负面结果、安全、监管、诉讼、公司回应和后续状态。

来源与引用审计

回查叶节点、去重转载、校验引语/数字与来源独立性。

Quick 使用生态、技术、反证和来源审计；Standard 增加工商、人物、产品；Deep 使用全部八类角色。

10. 导入本地 HTML/JSON

npm start -- research '以参考页为起点，重新核验并扩展公司全景' \
  --seed '/absolute/path/reference.html' \
  --harness codex \
  --depth deep \
  --max-agents 64 \
  --entities-per-agent 12 \
  --concurrency 6 \
  --out reports/result.md

Seed 会被解析成实体、法律主体、别名、创始人、融资、观点和技术字段，然后按角色分片。它只是待核验基线，不会直接变成最终证据。

CLI 默认允许本地 seed；HTTP 服务默认禁止。API 需要时必须以 --allow-local-seeds 启动，而且只应向可信调用者开放。

12. 输出报告

Markdown

结论摘要、关键发现、实体脉络、风险、待验证、证据账本和来源注册表。引用均为可点击 [S编号]。

交互 HTML

独立离线文件；全文搜索、角色/置信度筛选、worker 工作契约、来源域名筛选、证据展开与 JSON 导出。

# 默认：result.md + result.html
--out reports/result.md

# 分别指定
--out output/report.md --html-out public/report.html

# 只生成 Markdown
--out reports/result.md --no-html

URL 会移除常见跟踪参数并去重。正文多次引用同一个来源是正常的，不等于来源重复计数。

export RESEARCH_HARNESS_API_TOKEN="$(openssl rand -hex 32)"

浏览器打开 http://127.0.0.1:8787/ui，输入 Bearer token、Harness、深度、并发和课题。

  • 总进度、耗时、活动 subagent、来源数与最后心跳。
  • Planner、角色 worker 和综合器的独立卡片。
  • 实时日志搜索与活动/心跳/发现/错误筛选。
  • 取消当前浏览器请求。
  • 完成后搜索报告、筛选来源、下载 Markdown、打开交互 HTML。
不要把服务直接暴露到公网。需要公网时使用 TLS、VPN/ACL、限流、费用配额和长随机 token；不要对不可信调用者开放本地 seed。

14. HTTP API 与 SSE

除 UI 页面外，健康检查和研究接口均要求 Bearer 鉴权。

同步接口

curl http://127.0.0.1:8787/v1/research \
  -H "Authorization: Bearer $RESEARCH_HARNESS_API_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{
    "topic":"调研异步 Agentic RL 的学界与工业界现状",
    "harness":"codex",
    "depth":"deep",
    "language":"zh-CN",
    "maxQueries":6,
    "maxAgents":64,
    "entitiesPerAgent":12,
    "maxSources":20,
    "subworkMode":"hybrid",
    "concurrency":6
  }'

SSE 流式接口

curl -N http://127.0.0.1:8787/v1/research/stream \
  -H "Authorization: Bearer $RESEARCH_HARNESS_API_TOKEN" \
  -H 'Content-Type: application/json' \
  -H 'Accept: text/event-stream' \
  -d '{"topic":"调研异步 Agentic RL","provider":"codex","depth":"deep","maxAgents":64,"concurrency":6}'

事件依次为 connected、多个 progress，最后是 result；失败时是 error。结果包含 Markdown、HTML、tasks、evidenceTasks、failedTasks 和 sources。

字段限制
topic / brief3–500 / 最长 4000 字符
depthquick / standard / deep
maxQueries2–8
maxAgents2–256
entitiesPerAgent1–50
maxSources2–30
concurrency1–16
includeDomains / excludeDomains各最多 20

请求 schema 是 strict 的，不接收 Provider token 或未知字段。

15. Node.js / TypeScript 调用

import { createAgent, createCliProgressReporter, ResearchWorkflow } from "research-harness";

const workflow = new ResearchWorkflow(createAgent("codex"), {
  concurrency: 6,
  heartbeatIntervalMs: 5_000,
  onProgress: createCliProgressReporter({ format: "human" })
});

const result = await workflow.run({
  topic: "调研异步 Agentic RL",
  provider: "codex",
  depth: "deep",
  language: "zh-CN",
  maxAgents: 64,
  entitiesPerAgent: 12,
  maxSources: 20,
  subworkMode: "hybrid",
  concurrency: 6,
  includeDomains: [],
  excludeDomains: []
});

console.log(result.markdown);
console.log({ sources: result.sources.length, failed: result.failedTasks.length });

包还导出 HTTP app、dashboard renderer、交互报告 renderer、seed parser、task graph、角色定义和结构化事件类型。

16. 质量门槛与自动修复

  1. 规划、Evidence、综合都必须符合 JSON Schema。
  2. 本地先修代码围栏、智能引号、尾逗号等机械问题。
  3. 仍失败时最多运行两个禁网 repair，只修结构和引用。
  4. 单个 evidence worker 连续失败后隔离，其他任务继续。
  5. 少于两个不同 HTTP(S) 来源、未知引用无法消除或最终报告引用不足时，整次运行失败。

每个来源必须进入注册表；综合器引用的 S编号 和 URL 必须一致。反证、冲突、无法访问和未解决问题不会被静默删除。

17. 性能、时间与成本调优

# 快速试题
--depth quick --max-agents 12 --max-sources 6 --concurrency 3

# 日常深度
--depth standard --max-agents 32 --max-sources 12 --concurrency 4

# 全景尽调
--depth deep --max-agents 64 --max-sources 20 --concurrency 6
调高参数覆盖面墙钟时间总成本
maxAgents明显增加增加明显增加
maxSources单包更深增加增加
concurrency基本不变通常下降基本不变或略升
maxQueries查询维度增加增加增加

推荐先 Quick 检查题目和术语，再 Deep 生成最终报告。长尾 worker 运行 5–15 分钟并不必然是卡死，只要仍有心跳或工具活动。

18. 安全与凭据

  • Provider key 只放环境变量，不写 topic、brief、命令行、HTTP body 或 seed。
  • Codex 使用只读临时会话；CC 使用临时空目录、safe mode 和工具 allowlist。
  • OpenAI 请求设置 store:false。
  • 服务端 API token 与 Provider key 分离。
  • UI 中 token 只保存在页面内存；HTML 使用安全 DOM sink，链接限制为 HTTP(S)。
  • 保存进度日志前检查内部课题、查询词和本地文件路径是否敏感。

19. 常见故障排查

找不到 Codex / Claude Code
command -v codex
codex --version
codex login

command -v claude
claude auth status
自定义路径可设置 CODEX_COMMAND 或 CLAUDE_COMMAND。
OPENAI_API_KEY / API token 缺失
export OPENAI_API_KEY='...'
export RESEARCH_HARNESS_API_TOKEN="$(openssl rand -hex 32)"
确保变量与 npm 进程处于同一个 shell 或进程环境。
Planning output 不符合 JSON Schema
框架会自动规范化并最多修复两次。仍失败时，减少相互冲突的要求、换更可靠的结构化输出模型、保存 JSONL 日志，并运行 npm run check。
Codex evidence run failed
常见原因是登录过期、网络失败、输出结构失败或并发过高。框架会重试并隔离单包；可把并发降至 2–4。
一直显示“仍在运行”
检查心跳是否更新、是否有 web_search/WebFetch 活动、worker 编号是否增长、其他 worker 是否补位。Deep 长尾属正常；若全局完全停止再终止。
API 无法读取 seedPath
以 npm start -- serve --allow-local-seeds 启动，并使用服务端可见的绝对路径。
HTML 文件很大
Deep HTML 内嵌完整证据，数 MB 正常。可降低 maxAgents/maxSources、主要阅读 Markdown，或使用 --no-html。
